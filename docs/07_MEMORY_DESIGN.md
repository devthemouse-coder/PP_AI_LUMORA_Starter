# 07. Memory 설계

## 1. 기억 유형

이 문서는 개념 개요입니다. 실제 구현에 필요한 관계·수명 주기·구조화 사실 및 삭제 정책은 [16. Memory 설계](./16_MEMORY_DESIGN.md)를 기준으로 합니다.

| 유형 | 설명 | 예 |
|---|---|---|
| Profile | 비교적 지속적인 사용자 선호·프로필 | 선호 언어 |
| Fact | 검증 가능한 구조화 사실 | 직원 생일 |
| Episodic | 과거 대화·사건의 요약 | 회의에서 합의한 내용 |
| Procedural | 반복 업무 절차 | 보고서 작성 규칙 |

## 2. 기억 데이터의 공통 메타데이터

- MemoryId
- Owner/User/Organization 범위
- MemoryType
- Subject 및 관계
- Value(민감한 경우 암호문)
- Source 및 SourceReference
- CreatedAtUtc / UpdatedAtUtc
- ValidFrom / ValidTo
- Confidence 또는 VerificationStatus
- Revision
- IsDeleted 또는 상태

실제 스키마는 보안·검색·이력 정책 검토 후 확정합니다.

## 3. 저장 흐름

1. 사용자 입력 수신
2. LLM이 기억 후보를 구조화
3. DTO 스키마 검증
4. 필수 값 및 날짜 검증
5. 소유자·권한 검증
6. 기존 기억과 충돌 확인
7. 모호하거나 충돌하면 사용자에게 확인
8. 승인 후 암호화 및 저장
9. 저장 결과를 사용자에게 알림

LLM이 추출한 값은 제안일 뿐이며, 검증 전에는 사실로 저장하지 않습니다.

## 4. 조회 흐름

- 질문 의도를 분류합니다.
- 허용된 Query Handler를 선택합니다.
- 현재 날짜·시간과 시간대를 명시적으로 전달합니다.
- 서버가 사용자 범위와 권한을 확인합니다.
- Repository가 매개변수화된 조회를 수행합니다.
- 필요한 필드를 복호화합니다.
- 실제 조회 결과를 근거로 답변을 생성합니다.

## 5. 정확성 정책

- 검색 결과가 없으면 없다고 답합니다.
- 날짜 기준이 모호하면 시간대 또는 기간을 확인합니다.
- 상충하는 기억은 임의로 하나를 선택하지 않습니다.
- 수정·삭제는 대상 기억을 명확히 식별합니다.
- 사용자가 정정하면 기존 이력과 새 값을 구분합니다.
- LLM이 만들어낸 추론과 DB에 저장된 사실을 구분합니다.

## 6. 기억과 모델 학습 구분

- Memory: DB에 저장하고 검색하는 것
- Procedural Improvement: 사용자의 수정·승인을 절차 규칙에 반영하는 것
- Fine-tuning: 모델 가중치를 변경하는 별도 학습 작업

초기 제품은 Memory와 제한적인 절차 개선을 다룹니다. 사용자 기억을 자동으로 모델 학습 데이터에 넣지 않습니다.
