# 34. 로컬 AI 연결 보안

## 네트워크 경계

Ollama Adapter는 `127.0.0.1` 또는 IPv6 loopback `::1`의 포트 `11434`만 허용합니다. 숫자 IP만 파싱하므로 DNS 재바인딩·호스트명 우회를 허용하지 않으며, 프록시와 redirect를 비활성화합니다. 연결 및 응답 크기를 제한하고 응답 본문을 로그에 남기지 않습니다.

이 정책은 이 애플리케이션이 Ollama에 요청하는 연결을 loopback에 제한합니다. Windows 방화벽을 변경하지 않으며, Ollama가 자체적으로 수행할 수 있는 네트워크 동작이나 같은 PC의 다른 프로세스에 대한 접근 제어를 대신하지 않습니다. 방화벽·Ollama bind 설정은 운영자가 별도로 확인해야 합니다.

## 데이터 전송과 모델 다운로드

대화 요청은 설정된 loopback Ollama로만 전송됩니다. 외부 AI Provider, 외부 fallback, 자동 모델 설치 및 다운로드 경로는 없습니다. Chat에 제공된 메시지와 제한된 최근 대화 기록은 로컬 모델 의도 추출에 사용되며, 외부 서비스로 전달되지 않습니다.

모델 다운로드가 필요한 경우 사용자가 출처, 라이선스, 양자화, 메모리 요구사항과 네트워크 동작을 확인한 후 별도 승인 절차로 수행해야 합니다.

## API 노출

`/api/llm/*`, `/api/chat`, `/api/conversations/*` 경로는 `Development` 환경에서만 매핑됩니다. 운영 환경에는 해당 경로가 없습니다. 개발 API는 고정된 개발 Tenant/User scope만 사용하고 scope가 없으면 fail-closed 합니다. 개발 서버는 loopback에 바인딩하고 외부 네트워크에 노출하지 마십시오. 사용자 인증·인가가 구현되기 전까지 인터넷 또는 신뢰할 수 없는 네트워크에서 API를 실행하지 않아야 합니다.

## 오류·로그

Application 오류는 제한된 오류 종류만 전달합니다. API는 공통 Problem Details로 응답하고 내부 예외 메시지나 원격 응답 본문을 노출하지 않습니다. 로깅 시 모델 상세·대화·암호화 정보·HTTP 응답 본문을 기록하지 않습니다.

## 남은 위협과 점검

- 로컬 관리자 또는 같은 사용자 권한의 프로세스가 Ollama runtime을 바꾸거나 loopback 서비스를 가장할 수 있음
- Ollama 자체의 외부 네트워크 동작 및 Windows 방화벽 규칙은 코드에서 통제하지 않음
- localhost API는 runtime 인증을 제공하지 않음
- 추론 Adapter 및 합성 입력 처리 테스트는 있지만 운영 모델 평가·장기 안정성 검증은 아님
- 모델의 JSON만 신뢰하지 않고 사용자 메시지에서 이름·날짜 근거를 다시 확인하지만, 자연어 해석의 모든 오류를 방지하지는 못함
- API 운영 공개 전 인증·인가, bind 주소, 방화벽 및 로컬 프로세스 위협을 별도로 검토해야 함
