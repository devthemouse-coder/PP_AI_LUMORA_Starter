# 26. 암호화 키 복구 안내

## 1. 키 구성

현재 구현은 서로 독립된 32바이트 AES-256-GCM 키와 HMAC-SHA-256 검색 키를 사용합니다. 각 키에는 별도 Key ID가 있고, 각 DPAPI 파일에는 키 ID 및 보호된 키가 저장됩니다.

- 기본 DPAPI 디렉터리: `%LOCALAPPDATA%\P.P. AI - LUMORA\keys`
- 설정 대체: `Security:KeyDirectory`, `LUMORA_KEY_DIRECTORY`
- DPAPI 범위: Windows `CurrentUser`. 같은 사용자 프로필에서 우선 복구하되, 다른 PC/사용자 프로필에서 단순 파일 복사를 통한 복구를 보장하지 않습니다.
- 새 설치 시에만 `--initialize-keys`로 키를 생성합니다. 저장소가 비었는지 확인하는 절차이며 운영 데이터에 새 키를 덮어쓰지 않습니다.

## 2. 복구 파일 보호 형식

`.lumora-keys` 포맷 버전 1은 다음을 사용합니다.

- 사용자 제공 비밀번호(최소 12자)
- PBKDF2-HMAC-SHA-256, 600,000 반복, 무작위 16바이트 Salt
- PBKDF2 결과 32바이트를 AES-256-GCM 키로 사용
- 무작위 12바이트 Nonce, 16바이트 인증 태그
- 포맷 버전, KDF 반복 수, Salt를 AAD로 인증
- 암호화 Payload에 AES Key ID/키, HMAC Key ID/키를 함께 보관하되 복구 파일 밖에는 평문으로 기록하지 않음

복구 비밀번호는 파일이나 앱 설정에 저장되지 않습니다. 비밀번호를 파일에 기록하거나 명령행 인수로 전달하지 마십시오. PBKDF2 반복 수는 포맷 버전의 고정 값입니다. 변경 시 호환 포맷 버전이 필요합니다.

## 3. 내보내기 및 가져오기

키 복구 파일 내보내기:

```powershell
dotnet run --project src\Lumora.Api\Lumora.Api.csproj -- --export-key-recovery 'F:\Offline-Lumora-Keys\lumora.lumora-keys'
```

다른 PC 또는 Windows 사용자에서 가져오기:

```powershell
$env:LUMORA_KEY_DIRECTORY = Join-Path $env:LOCALAPPDATA 'P.P. AI - LUMORA\keys'
dotnet run --project src\Lumora.Api\Lumora.Api.csproj -- --import-key-recovery 'F:\Offline-Lumora-Keys\lumora.lumora-keys'
```

가져오기는 현재 계정의 DPAPI로 다시 보호한 뒤 staging 파일을 다시 읽어 키와 Key ID를 검증하고, 새 디렉터리를 원자 이동합니다. 대상 키 경로가 이미 존재하면 실패하며 기존 키를 덮어쓰지 않습니다. 손상된 디렉터리는 삭제하지 말고 원본 그대로 보존한 뒤 새로운 빈 경로를 설정하십시오.

복구 파일은 백업 파일과 다른 디렉터리/오프라인 매체에 둡니다. 같은 저장장치/가방/백업 계정에 두 파일과 복구 비밀번호를 모두 두면 분리 보호 효과가 줄어듭니다.

## 4. 시나리오 및 지원 범위

| 시나리오 | 예상 동작 |
|---|---|
| 같은 PC/같은 Windows 사용자, DPAPI 파일 정상 | 해당 DPAPI 사용자 프로필에서 키를 읽을 수 있습니다. 현재 설치 환경에서의 키 파일 복구 절차 자체를 별도 장애/재설치 시나리오로 검증한 것은 아닙니다. |
| 같은 PC에서 다른 Windows 사용자 | 기존 DPAPI 파일만으로는 복구를 보장하지 않습니다. 복구 파일과 별도 비밀번호를 새 사용자로 가져와야 합니다. 이 사용자 전환 시나리오는 실기 테스트하지 않았습니다. |
| 다른 Windows PC | 복구 파일과 별도 비밀번호를 대상 PC의 사용자로 가져온 후 백업을 복원하도록 구현되어 있습니다. 가져오기와 복원 코드는 같은 테스트 Windows 사용자에서 서로 다른 임시 DPAPI 키 디렉터리로 검증했지만, 실제 별도 PC에서의 복구는 검증하지 않았습니다. |
| 키 파일 손상/분실 | 새 키로 대체하지 않습니다. 검증된 키 복구 파일로 새 빈 키 디렉터리에 복구합니다. |
| DB 백업만 있고 키 복구 파일 없음 | DPAPI 원본 키 파일을 해당 사용자 프로필에서 사용할 수 있을 때만 복구를 시도합니다. 키가 영구 분실되면 암호화된 본문 및 HMAC 검색은 복구할 수 없습니다. |
| 키 복구 파일만 있고 DB 없음 | 키만 복구됩니다. 원본 DB/백업이 없으면 사용자 데이터를 재구성하지 못합니다. |
| 복구 파일 손상 또는 비밀번호 오류 | AES-GCM 인증 실패로 가져오기를 중단합니다. 부분 DPAPI 키 저장소를 만들지 않습니다. |

테스트는 합성 키로 복구 파일을 만들고, 잘못된 비밀번호 및 파일 변조를 거부하며, 키 ID와 AES/HMAC 키가 원본과 일치하는지 확인했습니다. DPAPI 가져오기는 동일 테스트 Windows 계정의 새 디렉터리에서 검증했습니다. OS 계정 변경 및 별도 PC에서의 DPAPI 재보호는 실기 검증되지 않았으므로 운영 전 별도 장비에서 복구 훈련을 해야 합니다.

## 5. 키 회전 및 폐기

복수 Key ID key ring, 회전, 재암호화, 검색 토큰 재생성, 이전 키 폐기는 아직 지원하지 않습니다. Key ID가 다르거나 필요한 키가 없으면 백업 복원은 실패합니다. 기존 DB가 있는데 `--initialize-keys`를 실행하거나 키 파일을 삭제/교체하지 마십시오.

복구 비밀번호를 잊거나 모든 키 복구 파일을 잃은 경우 안전한 우회 방법은 없습니다. 키 파일은 데이터베이스와 분리된 접근 제한 오프라인 매체에 보관하고, 복원 리허설 때 실제 운영 키를 사용하지 마십시오.
